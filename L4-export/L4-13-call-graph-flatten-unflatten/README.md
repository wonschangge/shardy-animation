## 核心结论

### 去重机制

- **判断依据**：两个函数的 **in/out 分片**。
- **动作**：把调用点**重定向**到同一个函数（`call @baz_0` → `call @baz`）。
- **`sdy.original_func_name`**：L4-12 outline 留下的**同源标记**，
  让去重知道「`@baz_0` 原本也叫 `baz`」。

### ★ `dedup-functions-fully` 的取舍

| | 默认（`false`） | `true` |
|---|---|---|
| **去重依据** | **按 in/out 分片** | **完全去重** |
| **分片不同时** | **不合并**（`@baz` / `@baz_0`） | **合并**（都用 `@baz`） |
| **函数数量** | 多 | **少** |
| **保守程度** | 保守 | 激进 |

**为什么 `true` 时合并可行**：**函数的分片信息在【调用点】上**
（`call ... {sdy.sharding = ...}`）。函数签名只是一个「默认约定」，
**真正的分片要求由调用点决定**。

这正是 L3-06 的 NOTE 说的：
`we ignore any arg/result shardings on the function`。

**收益**：函数更少 → IR 更小、编译更快。
**代价**：下游必须**总是读调用点的 sharding**。

**验收点答案**：看 in/out 分片是否相同 —— **相同则总是合并；不同则只有 `true` 才合并**。

### 用例差集

- **仅 `true` 有**：空分片情形、调用点数量不同 —— 因为完全去重时这些差异**不再阻止合并**。
- **默认专有**：参数分片与 call 实参**不一致**的情形 —— 保守模式下**会导致不合并**。

→ **测试设计原则**：每个选项都要有**针对该选项特有行为**的用例。
→ **方法论**：**差集分析**是理解「选项改变了什么」的捷径。

### 与 L4-12 的衔接

```
L4-12 outline:  named_computation × N  ->  @baz, @baz_0, ...   函数【变多】
L4-13 去重:     @baz, @baz_0, ...      ->  @baz                 函数【变少】
```

**为什么 L4-12 不直接去重**：outline 时是**局部视角**，处理一个实例时
不知道别处有没有同分片的；本课在**全局视角**下才能安全合并。
