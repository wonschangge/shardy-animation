1. 说出组的**两个规范化动作**（合并重叠 / 重编号）；
2. 说出**合并的判据**（传递闭包）与合并后采用哪个 id；

4. 说出**两条校验约束**（不跨界 / 形状相同）及其理由。

## 场景（6 幕）

1. 两个动作：合并重叠 + 重编号
2. **★ 合并规则：传递闭包**
3. **★ 重编号：任意 i64 → `0..N-1`**
4. 两条校验约束
5. 组的完整生命周期
6. 练习

## 核心结论

- **合并判据**：两个张量共享**任意一个** `group_id` → 属于同一组；
  **间接关联**（通过中间组）也算 —— 本质是**并查集**。
  合并后采用该组**最小的 id**。
- **重编号**：任意 `i64` → 紧凑的 `0..N-1`。
  **为什么紧凑**：后续"按组遍历"可以用数组而不是哈希表。
  排序依据：用例名 `reindex_ordering_matches_min_element_ordering` 点明"与最小元素顺序一致"。
- **两条校验约束**：
  1. **不能跨越 `manual_computation` 边界** —— 内部是"局部世界"，内外分片语义不可比
     （与 L2-09 的 manual 轴冻结同理）。4 个用例覆盖不同跨越方向。
  2. **同组的值形状必须相同** —— rank 不同则维度分片的项数都不同，"强制同分片"无从谈起。
- 另有 **2 个合法用例**（全在内部 / 全在外部）—— 锁定"不该报错的不报"。

### ⚠ 复现提示（实测踩过的坑）

RUN 行里的 `-split-input-file` **不能漏**：组 id 计数器是**按段重置**的。
漏掉它会让所有函数在同一模块里处理、共用一个计数器，编号变成 3、0、4 之类，与 CHECK 完全不符。
