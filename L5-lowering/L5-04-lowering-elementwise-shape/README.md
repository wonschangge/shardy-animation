## 核心结论

### ★ 核心判据

> **这个算子的「作用维」是不是被分片的那一维？**

| 算子 | 作用维 |
|---|---|
| `iota` | `dim`（生成序号的方向） |
| `slice` | 切片维 |
| `pad` | 填充维 |
| `concatenate` | 拼接维 |

- **未分片** → **直接局部化**（参数不变，只改类型）
- **被分片** → **需要补偿位置**

**为什么**：这些都是**位置相关**的算子 —— 输出依赖元素在全局中的位置。

### ★ `iota` 的偏移补偿

| 情形 | 处理 |
|---|---|
| 作用维**未**分片 | `dim` 不变，只改类型（值不需要调整） |
| 作用维**被**分片 | **本地 iota + 加偏移** |

**问题**：`iota dim=1` 在每台设备上都生成 `[0,1,2,3]`，但设备 1 该拿 `[4,5,6,7]`。

**解法**：`partition_id` + 查找表 `[0, 4, 8, 12]`（4 台设备各自的**起始序号**）。

**为什么不直接切全局 iota**：全局 iota 本身也要算出来（16 个值），
而「本地 iota（4 个值）+ 加偏移」**更省**。

### `slice`

| 参数 | 全局 | 局部 | 变化 |
|---|---|---|---|
| 第 0 维（**未分片**） | `4:12:2` | **`4:12:2`** | **不变** |
| 第 1 维（**分片**） | `0:32` | **`0:8`** | `32/4 = 8` |

**为什么切片维参数不变**：切片是**本地操作**，第 0 维没被分片
→ 每台设备看到的第 0 维都是完整的 16 → 「切哪里」是确定的。

### `concatenate` 与 `pad`

- **`concatenate`**：分片在**非拼接维**时直接转换（各操作数各自局部化，
  **拼接维大小不变**）—— 因为拼接是**逐元素对齐**的操作。
- **`pad`**（8 个用例，四种情形）：
  - 填充维未分片 → 参数不变
  - 全复制后 pad → 参数与全局一致
  - **分片维上 pad** → **uniform vs non-uniform**（只有首尾设备受影响）
  - **负 padding** → `pad` 兼具**裁剪**功能

### 统一套路

> 所有「位置相关」的算子都用同一个手法：
> **`partition_id` + 查找表**
> —— 与 L5-01 的常量、L5-02 的 `all_slice`、L5-03 的 dense 常量**完全一致**。
